Proposta definitiva — Setup Catalogo solo USB

Downgrade di stabilità · 20/11/2026 · nessun codice finché non autorizzi · fonte: decisione Renato (rinuncia BT)

Decisione di prodotto ricevuta: abbandono definitivo del collegamento Bluetooth e di tutto ciò che ne deriva per il setup del Catalogo. Obiettivo: un solo percorso (USB), superficie minima, regressioni sotto controllo.

0. Perché questo downgrade è la scelta giusta ora

Il ramo BT ha introdotto troppe variabili fuori dal controllo dell’app (pairing, cartella di ricezione, Share sheet, file (1)/(2), differenze OEM). Ogni iterazione ha allargato la superficie di test. Con un solo percorso USB possiamo congelare un happy path corto e verificabile.
Principio di stabilità: una sola modalità · testi unici · un set di file fisso · un checkpoint reale (import DATI_CIFS.json) · niente rami morti in UI.

2. Happy path congelato (unico)

1. Prerequisiti USB→ 2. Prepara set su Telefono→ 3. Copia 3 file su Desktop PC→ 4. Esegui CONFIGURA→ 5. Copia DATI_CIFS.json su Download→ 6. Import + CIFS + Attiva
  1. Telefono: Setup Catalogo → PC Windows → conferma prerequisiti (cavo dati, MTP).
  2. Telefono: tap Prepara file di configurazione → i 3 file finiscono in Download (nessun menu Condividi).
  3. Cavo: collega, Telefono sbloccato, modalità Trasferimento file / MTP.
  4. PC: Esplora file → Questo PC → Telefono → Memoria interna → Download → copia sul Desktop CONFIGURA.cmd, sup.ps1, QRCoder.dll (sovrascrivi; niente (1)).
  5. PC: doppio clic CONFIGURA → UAC → attendi «Tutto pronto» → compare DATI_CIFS.json.
  6. PC→Telefono: copia solo DATI_CIFS.json sul Download del Telefono.
  7. Telefono: l’app rileva il file (o Importa…) → Copia campi CIFS → Attiva Catalogo.
Nessuna fase «asincrona vuota». Le uniche porte sono: file preparati · script eseguito (inferito dall’arrivo di DATI_CIFS) · import OK · Catalogo attivato.

4. Piano tecnico di downgrade (cosa si modifica in codice, dopo OK)

PrioritàInterventoEffetto stabilità
P0 Rimuovere dalla UI: combo rami, testi pairing/BT, Share Intent, CTA «Invia set via BT» Un solo flusso; niente chooser
P0 Export sempre in Download; CTA «Prepara file…»; poi istruzioni MTP fisse Comportamento deterministico
P0 Ascolto solo Download/MediaStore + picker; rifiuto (1)/(2); maggiordomo Desktop resta Meno ambiguità file
P0 Riscrivere stringhe S0 / disponibilità / CIFS recovery senza BT Niente false piste
P1 Eliminare codice morto BT (composable legacy, enum rami, messaggi script BT) Meno regressioni future
P1 Nuovo PDF guida USB in assets; LOCK + guida test USB-only Allineamento docs↔app
P2 LAN announce: resta silenzioso, non documentato in guida Ancora di recupero senza complessità UX
Cosa non si tocca: generazione script Windows, creazione share MyMedia, form Copia CIFS, attivazione Catalogo via SAF, analogia locale/NAS/cloud (resta scheletro già presente, senza inventare BT).

5. Criteri anti-regressione (obbligatori prima del telefono)

  1. Unit test: export Download, parse DATI_CIFS, rifiuto (1), maggiordomo nello script, assenza stringhe BT nel percorso PC.
  2. assembleDebug + APK artifact con versionCode nuovo (proposta: 0.16.75).
  3. Checklist agente: nessun Intent.ACTION_SEND nel flusso PC; nessun ramo PcLinkMode in UI.
  4. Una sola guida test USB (passi numerati); LOCK USB-only con checkbox 1:1.
  5. Gate Cloud già in AGENTS.md: niente richiesta prova telefono se i punti sopra non sono verdi.
